# Thought Canvas v12.6 视觉与布局系统

设计方向：冷静、密集但不拥挤的桌面思考工具。视觉层级服务于目标、来源、模型能力、连接状态和关系，不用装饰掩盖信息结构。

## 1. 密度与画布语言

- 主画布点阵：14px；
- 用户/普通分支虚线：3/3；处理中虚线：4/3；
- 主内容保持高信息密度，但设置页与弹窗通过分组、边线和留白提高可扫描性；
- Compact、整理、归档等次级动作不与发送同权。

## 2. 字体与可读性

- 首页标题：约 34–42px；
- 顶部项目/目标/保存信息：13–15px；
- 节点标题：15px；
- 富文本正文：13px 以上，行高约 1.78；
- 设置主标题：26px；
- 设置供应商名称：14–15px；字段标签：13px；输入文字：14px；说明文字：至少 12px；
- 极低优先级元数据：10–11px，仅用于不影响操作判断的信息；
- 英文使用系统 sans-serif；日文优先系统日文字体，均保持与中文相同的字号层级和可点击尺寸。

低优先级信息可以降低对比度，但不能同时使用过小字号和过低对比度。

## 3. 颜色

- 背景：off-black；正文：off-white；
- 淡紫色：主要动作和模型结构，但不用于大面积输入框双层描边；
- 金色：待确认/注意；绿色：保存、连接或完成；红色：错误或破坏性操作；
- 工作状态、可信状态、连接状态必须有文字，不只靠颜色。

## 4. 焦点与输入框

- 鼠标点击输入框使用单层中性边框，不出现父级 outline + 输入框 outline 的双层紫框；
- 键盘 `:focus-visible` 仍必须清晰可辨；
- 输入框最小高度约 46px，主要按钮最小高度约 40px；
- 标签容器不因 `:focus-within` 再绘制第二个外框。

## 5. 顶部模块

项目、最终目标和保存状态是三个视觉独立、几何协调的模块：

```text
[项目与导航]        [最终目标 / 状态]        [保存状态]
[搜索与画布工具]
```

- 宽屏时目标保持画布区域水平居中；
- 目标文字居中，并在文字与卡片底边之间保留稳定留白；
- 搜索框左边缘与项目模块左边缘对齐；
- 中窄屏允许目标进入第二行，但仍保持独立边界；
- 独立模块不得通过层级或绝对定位互相覆盖；
- 待确认目标作为目标模块的附属卡，不成为第四个顶层浮窗。

## 6. 模型与思考等级选择器

- 使用应用内自定义菜单，避免浏览器原生下拉在暗色界面中出现突兀样式；
- 菜单优先显示在触发器上方，并保留至少 6px 间距；
- 模型菜单显示名称、ID、连接或能力信息；思考菜单只显示当前模型支持的等级；
- 当前项用勾选和文字状态表达；
- 隐藏原生 `<select>` 仅负责状态同步和辅助技术兼容，不占布局宽度；
- 模型和思考控件有独立宽度，不相互覆盖。

## 7. 设置页

- 最大内容宽度约 1380px；
- 左侧供应商列表条目增加高度、图标和行距；
- 右侧表单按“身份与协议 → 连接 → 模型 → 高级能力”分组；
- “连接并同步模型”是 API Key 供应商主动作；保存、测试和高级编辑降为次级；
- 普通保存按钮明确标注“保存非敏感配置”，避免用户误以为尚未验证的 Key 已经落盘；
- 连接状态使用标题 + 说明，成功后清空 Key 输入但保留“Key 已保存”；
- 模型行展示只读能力摘要，避免用户猜测思考等级来源；
- OAuth 页将状态、账号、套餐、模型和授权操作分成可扫描卡片。

## 8. 节点与右侧面板

节点展示类型、状态、标题、摘要、模型/思考等级和子节点进度；完整对话只在右侧面板出现。右侧顶部只显示一次主标题与路径，中间内容可滚动，底部输入区属于布局网格而非覆盖层。

## 9. 反馈

- 保存：正在保存、已保存、失败可重试；
- API Key 连接：正在验证、已连接、连接失败、已有 Key 未被覆盖、原连接仍可用；
- Codex：未安装、未连接、等待授权、已连接、取消、退出和错误；
- 生成：增量正文、停止按钮、部分回答标签和同消息续写；
- 创建节点：来源保留式聚焦与非阻塞提示；
- 错误信息必须可行动，不能只显示内部异常或 JSON。


## 10. 多语言布局

- 英文和日文文案可能比中文更长，按钮、标签、菜单和弹窗必须允许合理换行或弹性宽度；
- 语言选择器使用三种语言的自称：简体中文 / English / 日本語；
- 专有名词、模型 ID 和用户内容保持原文字体与文本，不做视觉伪翻译；
- 翻译不能通过缩小字号来强行塞入布局，优先增加宽度、换行或响应式重排。
