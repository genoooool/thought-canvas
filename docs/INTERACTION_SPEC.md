# Thought Canvas v12.6 交互规范

## 1. 界面语言

- 设置通用页提供简体中文、English、日本語；切换立即预览，保存后跨刷新保留；
- `document.lang`、日期和数字格式随语言切换；
- 项目标题、用户输入、模型回答、标注和推理对象不自动翻译；用户内容即使与 UI 词条同名也保持原样；
- 新生成请求默认使用所选界面语言回答，用户明确要求其他语言时以用户要求为准；
- 新增或更新 UI 文案时必须同步英文、日文词典和自动化测试。

## 2. 顶部区域

- 左：项目入口、标题、新建与设置；
- 中：当前目标、目标状态、待确认建议和上下文检查器入口；
- 右：保存状态；
- 宽度不足时目标区换到第二行，禁止项目、目标、保存状态互相覆盖。

## 3. 对话、模型与思考等级

- Enter 发送，Shift+Enter 换行；
- 每个发送入口包含供应商、模型、思考等级；
- 思考等级选项随当前模型能力变化，不支持的旧值自动回退为“自动”；
- 模型与思考菜单显示在触发器上方且不覆盖触发器；点击菜单外关闭；
- 输入框默认继续当前节点；节点右侧 `+` 创建分支，消息操作中的“从这里分支”以该消息为截止点；
- AI 回答增量显示；生成中可停止；停止或断线后已接收文本保留为部分回答；
- “继续完成”追加到同一条 assistant message，不制造重复消息。

## 4. 目标

AI 建议必须显示“采用 / 编辑后采用 / 暂不设置”。未确认建议可见，但不得进入 Prompt。

## 5. 选区、拆解与提炼

- 用户可以跨 Markdown 标题、粗体、引用、列表等元素拖选；
- 应用在 `selectionchange` 与操作按钮按下阶段保留选区，点击后不能因焦点变化误报“尚未选择文字”；
- “拆解选中文字”创建来源可追踪的内容模块；
- “提炼选中文字”创建观点、证据、假设、问题、方案、风险、行动或决策；
- 所有结果保存来源节点、消息 ID、原始 Markdown 字符范围和可见原文；
- 未选择文字时才显示明确提示，并允许用户关闭；
- 若格式复杂或选区过长导致原始 Markdown 字符范围无法唯一确定，保留准确可见文字并标记“原文范围未确定”，不能阻断操作；
- 拆解生成的内容模块立即拥有“拆解当前模块 / 拆解选中文字 / 提炼选中文字”，无需先追问。

## 6. API Key 供应商连接

主流程：

```text
选择/创建供应商
→ 确认协议和 Base URL
→ 输入 API Key
→ 点击“连接并同步模型”
→ 显示验证进度
→ 成功后显示“已连接 / Key 已保存”
→ 模型及思考等级立即同步到所有选择器
```

规则：

- 新 Key 连接失败不得覆盖旧 Key；
- 普通“保存非敏感配置”和自动保存不得写入 API Key；
- 未改变连接关键配置时，替换 Key 或重新同步失败后应恢复上一份已验证连接、模型目录和可生成状态；
- 前端成功后清空 Key 输入，不显示明文；
- 模型目录缺失时，可通过最小生成验证使用手工模型回退；
- 修改 Base URL、认证、协议或关键请求头后，已连接状态变为“待重新验证”；
- 高级模型编辑保留，但不取代主连接流程。

## 7. Codex 网页授权

未连接：显示 **连接 Codex** 和设备码备用入口，不允许把不可用 Codex 模型当作正常可选模型。

浏览器授权：

```text
点击连接 Codex
→ 预开新窗口
→ 本地 App Server 创建官方授权 URL
→ 新窗口跳转到 ChatGPT 授权
→ 页面轮询会话
→ 成功后显示账号、套餐和实际模型
→ 点击“立即使用 Codex”切换供应商/模型/思考等级
```

设备码授权显示一次性代码与 URL。两种授权均可取消，同一时刻只允许一个活动会话。退出登录后 Codex 模型重新禁用。Thought Canvas 不展示、复制或保存 OAuth Token。

## 8. 节点、标注与画布

- 新分支、拆解或汇总完成后聚焦新节点组；来源节点保留在可理解的视野边界；
- 切换节点默认从对话顶部阅读；当前节点发送或续写才滚到底部；
- 搜索覆盖节点标题、问题、消息、来源文本和推理对象；
- 当前路径模式隐藏无关分支但不改数据；
- 内容模块支持“返回来源”；小地图反映当前可见节点和视口；
- 节点右侧标注手柄支持点击快速创建，或拖拽到画布空白处指定落点；拖拽过程中显示密集虚线和位置预览；
- 标注类型包括标注、想法、问题、风险和行动，可编辑、继续追问、分支、拆解与提炼；
- 标注是辅助思考对象，不计入来源节点的主分支完成度；
- 有后续内容的节点可折叠，折叠只改变可见性，不删除数据；搜索命中被折叠后代时自动展开祖先路径。

## 9. 推理对象、比较与汇总

- 推理对象类型：观点、证据、假设、问题、方案、风险、行动、决策；
- 工作状态和可信状态分开编辑；
- 关系必须明确源对象、关系类型（支持/反驳/依赖）和目标对象；
- 恰好选择两个节点时提供比较，不隐式调用模型；
- 两个及以上节点可汇总；确认弹窗说明纳入内容与焦点；
- 汇总生成画布节点和决策对象，并记录模型与思考等级。

## 10. Compact、版本与导出

- Compact 属于次级操作；达到消息阈值可自动建议或触发；
- Compact 是派生摘要，不删除原消息；
- 版本记录列出时间、节点数、大小和更新时间；恢复前确认并自动备份当前状态；
- 导出提供完整 JSON、JSON Canvas、Markdown，并在完成后给出非阻塞反馈。

## 11. 弹窗与确认

- 新建分支和业务弹窗使用统一的标题、说明、字段标签、输入字号、按钮高度和留白；
- 供应商、模型和思考等级字段各自拥有最小宽度和状态说明，长文本不得被相邻控件覆盖；
- 项目删除、版本恢复、清除密钥、删除对象等使用应用内居中确认弹窗；
- 不调用浏览器原生 `confirm()` / `alert()`；破坏性操作必须明确说明影响范围和不可恢复性。

## 12. 可访问性

核心操作具有可读标签和键盘焦点；正文与设置说明不得依赖过小字号；状态不能只用颜色；隐藏原生 select 不可形成不可见占位；缩窄窗口时 Markdown、来源卡、顶部工具栏和设置表单不得横向覆盖。
