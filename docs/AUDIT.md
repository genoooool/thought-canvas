# Thought Canvas v12.6 产品审计与落地结果

## 原始优势

- 对话、显式分支、拆解、整理、Compact 和汇总已有清晰操作语义；
- 拆解绑定稳定消息并保留来源文本；
- Compact 不删除原消息；
- 本地文件、原子写入、备份和密钥隔离形成可靠基础。

## v12.0 已落地的可信思考链

1. AI 推测目标未经确认会污染后续回答 → 目标同意状态机；
2. 分支只能从整节点产生 → 消息级截止锚点；
3. 用户不知道模型看到了什么 → 不可变快照和上下文检查器；
4. 新节点在视口外 → 来源保留式聚焦；
5. 复杂画布难定位 → 搜索、当前路径、返回来源和小地图；
6. 对话无法形成长期结构 → 可追踪推理对象和语义关系；
7. 多分支只能“看见”不能比较 → 双分支比较；
8. 汇总缺少决策结构 → 决策对象、依据、风险和行动；
9. 长回答缺少控制 → 流式、停止、部分输出和同消息续写；
10. 备份和本地安全不可见 → 版本恢复、回环绑定、Host/Origin/会话令牌；
11. 迁移格式单一 → JSON Canvas 与 Markdown 导出；
12. 视觉节奏偏疏 → 14px 点阵、3/3 用户虚线、4/3 处理中虚线。

## 用户截图暴露并在 v12.2–v12.4 修复的问题

### 1. 选区操作误报

**现象**：蓝色高亮仍在，点击“拆解选中文字 / 提炼选中文字”却提示“尚未选择文字”。

**根因**：按钮点击导致焦点和 Selection 在 `click` 处理前变化，旧实现又依赖消息区域的特定鼠标事件。

**修复**：全局持续缓存 Selection，并在按钮按下阶段提前保存；支持跨 Markdown DOM 的范围映射与可见文本回退。浏览器回归测试不再合成旧 `mouseup`，仍能完成两种操作。

### 2. 顶部 UI 竞争和覆盖

**现象**：项目卡、目标卡和保存信息分别定位，宽屏空洞、窄屏重叠。

**修复**：重组为统一响应式工具栏，三段同一布局上下文；目标区在中窄屏换行，而不是覆盖项目区。

### 3. 模型下拉重叠和紫色框

**现象**：浏览器原生下拉覆盖控件，隐藏 select 仍占宽度，触发器附近有突兀紫色描边。

**修复**：应用内模型/思考菜单、上方定位和几何间距；隐藏原生 select 只做状态同步，不参与布局；焦点改为中性单层样式。

### 4. 设置页阅读负担

**现象**：供应商列表、字段标签、说明和输入文字偏小；输入框产生父子双层紫色边线。

**修复**：提高弹窗宽度、字号、行距、输入框和按钮高度；取消容器 `focus-within` 外框，保留清晰但克制的键盘焦点。

### 5. 供应商接入流程碎片化

**现象**：保存 Key、测试连接、同步模型相互分离；用户无法确认当前模型和能力是否真的来自账号。

**修复**：API Key 供应商提供“连接并同步模型”，验证成功后才保存 Key，并动态刷新模型与思考等级。连接失败保护旧 Key，前端不接收明文。

### 6. Codex 只有终端登录，不是一键接入

**现象**：临时实现可启动 CLI 登录与 `codex exec`，但授权完成后不能可靠读取账号模型，也不能形成宿主应用级流式会话。

**修复**：使用 Codex App Server 完成浏览器/设备码授权、账号与套餐读取、`model/list`、`thread/start`、`turn/start`、增量消息和 `turn/interrupt`。网页授权成功后可直接“立即使用 Codex”。

### 7. 缺少统一思考等级

**现象**：不同供应商支持的 effort/thinking 参数不同，UI 和生成记录都无法稳定表达。

**修复**：建立模型能力规范化层；所有入口使用统一等级，运行时按协议映射并限制在当前模型支持范围内。能力推断明确标记为 `inferred`，不冒充供应商保证。

## 仍坚持的设计约束

- 自然对话是默认，结构化对象由用户主动提升；
- AI 不能自动把推测目标、观点或证据变成事实；
- 完成状态与可信状态分离；
- 原文、消息、Compact 和快照不被派生结果覆盖；
- 自动布局只改变坐标，不改变语义；
- API Key 只有验证成功后保存，OAuth Token 不由 Thought Canvas 管理；
- 外部账号、网络、余额和模型灰度与本地产品 Gate 分开验收。
