# v12.6 画布布局与视觉节奏

## 1. 语义列与树布局

画布按语义深度从左到右阅读。每条普通父子关系都满足
`child.x = parent.x + COLUMN_GAP`；碰撞不能制造额外列，后代也不能折回父节点左侧。

- 父节点只有一个普通子节点时，两者中心 Y 对齐；
- 父节点有多个子节点时，按稳定顺序竖排，首尾子节点中心的中点与父节点中心对齐；
- 同组根节点间使用 `NODE_GAP`，跨组使用 `GROUP_GAP`；
- 排序键固定为 `layoutOrder → sectionOrder → createdAt → id`。

## 2. 拆解与后续分支

同一父节点、同一 `decomposition:*` 组的模块必须在父节点右侧同一列由上到下排列。它们不是一条横向流水线。每个模块自己的追问、回答或递归拆解再从该模块右侧进入下一列。

```text
来源节点 ───┬── 模块 1 ─── 后续
            ├── 模块 2
            ├── 模块 3 ─── 再次拆解（同列竖排）
            └── 模块 4
```

## 3. 确定性轮廓布局

`layout-engine.js` 对每棵子树计算逐深度的上下轮廓。兄弟子树只按实际重合的语义列求最小纵向位移，再合并轮廓；深分支不会用整个包围盒把其他顶层模块推到极端位置。局部布局完成后，以直接子节点的首尾中心重新对齐父节点。

核心计算是无 DOM、无全局状态的纯函数。相同节点数据和高度必然产生完全相同的坐标，连续执行两次“自动排布”不得漂移。

## 4. 完整排布与增量排布

完整排布重算自动节点，同时保留手动标注坐标。主树、孤立树、merge/summary 和 annotation 分别作为完整子树单元；不同单元冲突时 x 保持语义固定，只选择距离期望位置最近的合法纵向平移。

增量排布固定已稳定节点。一次新增的 `parentId + groupId` 及其新后代先在局部完成布局，再作为一个整体纵向避让；不得通过向右跳列躲避，也不得移动无关分支。

merge/summary 位于最右来源节点的下一列；其后代从 merge 的实际 x 继续向右。自动 annotation 的后代遵守相同规则；`annotationManualPosition` 节点保持用户坐标，其他自动单元绕开它。

## 5. 聚焦规则

- 单节点：完整进入视口并保留合理边距；
- 分支：同时展示来源节点和新节点；
- 拆解：展示来源节点与本次新建模块组；
- 汇总：展示来源选择与汇总节点；
- 用户已主动平移后，系统只在明确创建/定位动作时改变视口。

## 6. 画布导航

- 搜索定位时聚焦目标；
- 当前路径模式显示根—当前路径、直接下一步和相关 merge 来源；
- 小地图按可见世界坐标缩放，标出当前视口；
- “适配全部”是用户主动动作，不代替新节点的局部聚焦。

## 7. 分组和碰撞

`answer`、`decomposition`、`merge` 使用独立 groupId；组间距大于普通节点间距。归档节点不参与可见碰撞计算。自动布局只改坐标和布局稳定标记，不改内容、消息、边、`parentId`、`groupId` 或语义顺序。

主树内部由轮廓布局直接消除重叠；不同树单元使用“禁用 dy 区间”求最近合法纵移。禁止有限次随机网格搜索、逐节点修补或按碰撞次数增加横向列。

## 8. 连线

- 默认曲线，可切换直角线；
- 默认实线，可切换虚线；
- 用户虚线：`3 3`，圆角线帽；
- 处理中虚线：`4 3`，带缓慢流动动画；
- 分支、拆解、merge 使用 relation 标签和不同语义类；
- JSON Canvas 导出把这些关系转换为带 label 的边。

## 9. 网格与尺寸

- 主画布点阵：14px；
- 节点布局宽度：约 308px；
- 内容高度在最小 170px 与最大 224px 之间估算；
- 语义列间距：430px；同组节点间距：38px；跨组间距：88px；
- 右侧栏宽度可在 360–680px 之间调整；
- 顶部网格在 1320px 以下改为两行。

布局完成后按整体 bounds 扩展世界尺寸。禁止对节点逐个截断坐标，因为这会破坏子树内部相对位置。

## 10. 可执行不变量

纯布局测试和浏览器 gate 共同检查：拆解同列、稳定顺序、父子恰好相差一列、唯一子节点中心对齐、多子节点首尾中心对齐、无矩形重叠、无回折、宽度只由真实深度决定、重复排布坐标相同、增量新增不移动无关稳定节点、手动标注坐标不变。浏览器 gate 另外用真实 DOM 矩形验证所有未归档可见节点无重叠。
