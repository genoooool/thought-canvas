# v12 汇总与决策策略

## 1. 汇总的目的

汇总不是简单压缩，而是把多个探索分支转成一个可继续推进、可审计的决策节点。

## 2. 输入规划

选择父节点和后代时：

1. 有独立回答的节点进入正文；
2. 没有独立回答但承担路径关系的节点作为路径上下文；
3. 已被所选 merge 节点覆盖的旧来源去重；
4. 每个来源保留节点 ID、问题、模型、上下文快照和开放问题；
5. 用户可在确认弹窗填写本次最想解决的焦点。

## 3. 不可变 merge 快照

汇总前创建专用 ContextSnapshot，记录选中节点、来源内容、当前已确认目标、约束和汇总焦点。GenerationRecord 的 `purpose` 为 `merge`，引用该快照。

## 4. 输出

汇总同时创建：

- `merge_summary` 画布节点；
- AI 汇总消息；
- `decision` 推理对象。

决策对象至少包含：

```text
最终选择
依据
支持证据
被排除或未采用的方向
未解决风险
下一步行动
来源节点
目标版本
上下文快照
```

## 5. 冲突

汇总不得把未解决冲突伪装成共识。支持、反驳和依赖关系会进入汇总上下文；仍未解决的冲突应落在风险或开放问题中。
